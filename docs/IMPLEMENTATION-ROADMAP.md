# SHOPNEX — خارطة تنفيذ وتسليم

**الحالة:** تحديث تنفيذي في الفرع `feature/purchasing-accounting-analytics-zatca-qr` المبني على الإصدار المنشور `0.2.0`. تبقى النسخة الدائمة على GitHub Pages موقع معاينة ثابتًا حتى دمج هذا الفرع؛ لا يتصل الموقع بقاعدة API سحابية ولا يحفظ معاملات زوار الموقع.

## ما أُنجز في هذا التحديث

1. **المشتريات:** موردون وفاتورة مشتريات مسجلة ببنود الخادم والخصم والضريبة والاستلام الكامل للمخزون والدفعات الجزئية/الكاملة ورصيد المورد.
2. **التكلفة والمخزون:** حركات قابلة للتتبع وتكلفة مرجحة مخزنة عند الاستلام، مع لقطات مالية للفاتورة. البيع يستخدم التكلفة المخزنة لقيمة COGS.
3. **المحاسبة:** دليل أساسي، قيود مزدوجة متوازنة للمبيعات والمشتريات والسداد والأرصدة الافتتاحية، منع تكرار مصدر القيد، ميزان مراجعة وأستاذ وذمم.
4. **الضريبة:** تصنيفات وقواعد VAT مؤرخة بنسخة وسجل أثر على البنود، تحقق حدود التداخل، وسبب معاملة حين تشترطه قاعدة الضريبة.
5. **التقارير:** فترة تاريخ محلية بتوقيت الرياض، مبيعات ومشتريات ومدفوعات وضريبة تقديرية وذمم ومخزون وتكلفة وربح إجمالي وتحليل منتج/مورد واتجاهات يومية، وتصدير CSV.
6. **زاتكا:** QR محلي صحيح البنية لوسوم TLV الأساسية 1–5، مع عرض لقيمه وتحذير ظاهر. لا اتصال خارجي أو إقرار Phase 2.
7. **الواجهة:** شاشات RTL/LTR للشراء والمحاسبة والتحليلات وQR، بيانات معاينة ووسم واضح للموقع العام، وتجزئة تحميل صفحات الرسوم.

## التحقق

- `pytest`: 16 اختبار API وتكامل ناجحة، تشمل توازن القيود، الاستلام والدفعات، التكرار، التداخل الضريبي وترميز QR.
- `pnpm --dir apps/desktop check` و`build`: ناجحان محليًا دون تحذير حجم بعد فصل React والرسوم إلى chunks مستقلة.
- `alembic upgrade head`: ناجح على قاعدة SQLite مؤقتة جديدة.
- فحص مرئي لشاشات المشتريات وميزان المراجعة ولوحة التقارير في المعاينة العربية الداكنة.

## ضوابط الحساب

- الخادم وقاعدة البيانات مرجع السعر والخصم والضريبة والمخزون؛ لا يقبل API إجماليات يرسلها المتصفح. تستخدم أموال الخادم `Decimal` وتقريب نصف لأعلى، وواجهة المال وحدات صحيحة/BigInt.
- تعد أرقام التقارير والهامش وVAT تقديرية من السجلات المحفوظة. ليست إقرارًا رسميًا؛ لا تشمل مصروفات/تصحيحات/أهلية خصم ضريبة مدخلات إلا بعد وجود مصدرها وسجلها في التطبيق.
- لا تُنشأ سطور أو مدفوعات أو تكلفة تاريخية بأثر رجعي إذا لم تكن موجودة في الإصدار السابق.

## التوصية

يُنشر الإصدار بعد مراجعة CI، مع إبقاء الموقع العام بمسمى «معاينة». لا تستخدم معاينة GitHub Pages لتسجيل مشتريات أو فواتير منشأة فعلية؛ أتمم استضافة API/قاعدة البيانات وسياسات الأمن والنسخ أولًا. ابدأ بعد ذلك بعزل الشركات والفروع ثم أوامر الشراء والمرتجعات/الإشعارات وعمليات محاسبة الإقفال، وأطلق ZATCA Phase 2 فقط بعد اجتياز SDK وSandbox الرسميين لحساب المكلف.
