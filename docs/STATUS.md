# حالة SHOPNEX ULTIMATE — الإصدار 0.2.0

## ما يتضمنه الإصدار

واجهة React/TypeScript عربية RTL مع تبديل الإنجليزية، ولوحة قيادة، وأساس المبيعات والمخزون والإعدادات، وشاشة إعداد ZATCA. تمت إضافة وحدات عملية أولية للمطاعم والمطبخ وCRM والولاء ودليل الموظفين.

تدعم وحدات الإصدار الإضافة والتحديث عبر API محلية محمية، مع تخزين سجلات الشركة في قاعدة البيانات المحلية. تشمل المطاعم الطلبات والطاولات وحالات الطلب؛ ويشمل CRM دليل العملاء وشرائحهم ونقاط الولاء؛ وتشمل HR دليل الموظفين وحالة العمل الأساسية. وضع العرض التجريبي لا يحفظ بياناته.

## الحزم المتاحة

- **Windows x64:** مُثبت واجهة `setup.exe` وحزمة كاملة تتضمن مصدر API وسكربت تثبيت بنقرة مزدوجة ومشغّلًا يجهز API؛ تتطلب API وجود Python واتصال الإنترنت لتنزيل الاعتماديات أول مرة.
- **Linux Debian/Ubuntu x86_64:** مُثبت واجهة `.deb`؛ خدمة FastAPI تُشغّل منفصلة عبر `scripts/run-api.sh`.
- لا توجد حزمة macOS.

مُثبت Windows مبني عبر cross-compilation ومتحقق من نوعه وبنية الحزمة، لكنه لم يُشغّل على جهاز Windows فعلي في بيئة البناء؛ وهو غير موقّع رقميًا وقد يظهر تحذير SmartScreen.

## حدود مهمة

وحدات المطاعم وCRM والموارد البشرية **MVP محدود** وليست نظام مطاعم/ERP كاملًا؛ لا تشمل الوصفات والمكونات أو تكامل الأجهزة أو الرواتب أو الحضور والانصراف أو التصدير الرسمي.

**لا يوجد إرسال أو Reporting أو Clearance فعلي إلى ZATCA/FATOORA**، ولا توليد أو توقيع XML/QR فعلي أو اختبار اتصال خارجي. لا تدّعي النسخة اعتماد ZATCA ولا تستخدم لإرسال فواتير ضريبية نظامية. يلزم مطابقة التكامل مع أحدث وثائق الجهة وSDK/Integration Sandbox وحساب المنشأة قبل التفعيل الإنتاجي. لا تضع أي اعتماد أو مفتاح إنتاجي في المستودع.

## التحقق المنفذ

- `pnpm --dir apps/desktop check` — اجتاز.
- `pnpm --dir apps/desktop build` — اجتاز؛ يوجد تحذير غير مانع من حجم JavaScript أكبر من 500 KB.
- `services/api/.venv/bin/python -m pytest -q` من مجلد `services/api` — **6 اختبارات ناجحة**.
- ترحيل Alembic إلى head على قاعدة SQLite مؤقتة — نجح؛ الترحيل الجديد يضيف جدولًا ولا يحذف الجداول السابقة.
- `pnpm desktop:build` — نجح بناء حزمة Debian/Ubuntu Linux amd64 للإصدار `0.2.0`.
- أضيف سير عمل GitHub Actions لتكرار فحوص الواجهة واختبارات API عند كل push أو pull request.

## التشغيل المحلي

من جذر المشروع شغّل `pnpm install` ثم `bash scripts/run-api.sh`. يطبق السكربت الترحيلات ويشغّل API على `127.0.0.1:8000`. استخدم `pnpm dev` للواجهة أو `pnpm desktop:dev` لتطبيق سطح المكتب بعد تشغيل API. احتفظ بنسخة احتياطية من قاعدة البيانات وملفات `.env` ومفتاح الجلسة المحلي قبل أي استبدال يدوي.
