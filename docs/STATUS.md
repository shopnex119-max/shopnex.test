# حالة SHOPNEX ULTIMATE

## النسخة المنشورة

الفرع الافتراضي `main` ما زال على النسخة المنشورة `0.2.0` كما يوضح README. يحتفظ هذا الفرع بتاريخ Git الأصلي؛ لم يُحذف المستودع أو يُعدّل `main`.

## دفعة التطوير على GitHub

رُفعت التغييرات إلى `feature/pos-kds-guest-financial-core` وفُتح طلب مراجعة **مسودة** رقم [#1](https://github.com/shopnex119-max/shopnex.test/pull/1). لم تُدمج الدفعة بعد.

- شاشات كاشير ومطبخ وضيف عربية/إنجليزية، وتحسينات للوضع الفاتح والداكن.
- شاشة منتجات متصلة بالـAPI المحلي لإضافة السعر والضريبة والرصيد وقراءة الفواتير المحفوظة.
- محرك خادمي يستخدم `Decimal` والتقريب التجاري إلى الهلة؛ يأخذ السعر والضريبة من كتالوج الخادم، لا من الواجهة.
- إنشاء الفاتورة يسجل البنود والمدفوعات الصافية وحركات المخزون للمستخدم، ويحدث الرصيد في معاملة ذرية. يدعم ضريبة شاملة أو غير شاملة وخصومات ومدفوعات جزئية والباقي النقدي.
- ترحيل Alembic `9c31ef702ad4` يحافظ على بيانات المنتجات والفواتير القديمة؛ لا يخترع تفاصيل أسطر ومدفوعات تاريخية لم تكن محفوظة.

شاشة الضيف معاينة فقط ولا ترسل طلبًا إلى API. المطبخ يتصل بالسجلات الحالية عند تسجيل الدخول، لكن لا يتوفر تدفق مطبخ حي كامل لمحطات وتجهيز الأصناف. المخزون هنا كتالوج محلي دون توزيع حقيقي بين المستودعات والفروع.

## التحقق

- `pnpm --dir apps/desktop check` — ناجح.
- `pnpm --dir apps/desktop build` — ناجح؛ يظهر تحذير Vite غير مانع عن حجم ملف JavaScript الرئيسي (>500 KB).
- `cd services/api && .venv/bin/python -m pytest -q` — **12 اختبارًا ناجحًا**؛ تحذير deprecation واحد من Starlette/AnyIO.
- Alembic `upgrade head` — ناجح على قاعدة فارغة وقاعدة إصدار سابق محشوة بمنتج وفاتورة؛ رُحّلت القيم القديمة.
- اختبار HTTP على قاعدة مؤقتة: إعداد مالك، إنشاء منتج وبيع، وقراءة الإجمالي/الضريبة/الباقي ورصيد المنتج والفاتورة. أوقف خادم API المؤقت بعد الاختبار.
- فحص مرئي للواجهة بالمتصفح: POS والحساب الفوري، واجهة الضيف، KDS، وضع فاتح، ونموذج المنتج. رابط المعاينة المؤقت للواجهة هو للعرض فقط.

## ما لا يزال مطلوبًا قبل التشغيل المؤسسي

- محاسبة ذات قيد مزدوج، دفتر أستاذ، إقفال ورديات وصندوق، مرتجعات وإشعارات دائنة وتسويات كاملة.
- تدفق QR للضيف إلى API ثم للمطبخ، بث حي، طاولات ومحطات إعداد وصلاحيات QR.
- عزل كامل متعدد الشركات والفروع والمستودعات، الأدوار الدقيقة وسجل تدقيق عام.
- مزامنة عدم الاتصال، دعم أجهزة وطابعات مُختبرة، اختبارات ضغط وأمن ونسخ/استعادة وإصدار موقّع.
- لا يوجد اتصال فعلي أو اعتماد أو ادعاء امتثال لـZATCA/FATOORA. يجب استكمال المواصفات الحالية وSDK وSandbox قبل الإنتاج.
- لم تُنفذ المواصفة الرئيسية ذات الوحدات والعناوين العديدة كاملة. تفاصيل المراحل وشروط القبول في [`IMPLEMENTATION-ROADMAP.md`](IMPLEMENTATION-ROADMAP.md).
